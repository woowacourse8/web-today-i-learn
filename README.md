## 💡 생각해 보기 (Reflection)

### HTML
- 나만의 갤러리에서 사진 9장은 어떤 태그로 표현하는 것이 좋을까? 
  - 단순히 `<div>` 안에 `<img>` 태그를 나열할 수도 있지만, 의미론적(Semantic)으로는 목록을 나타내는 `<ul>`과 `<li>` 태그로 감싸는 것이 더 좋습니다. 스크린 리더나 검색 엔진이 "아, 이 부분은 9개의 이미지로 이루어진 목록이구나"라고 명확하게 인지할 수 있기 때문입니다.
- 시맨틱 태그로 문서를 구분할 때, 어떤 기준으로 섹션을 나누는 것이 좋을까?
  - '콘텐츠의 역할과 의미'를 기준으로 나눕니다. 페이지의 핵심 주제를 담은 영역은 `<main>`, 독립적으로 떼어내어 읽어도 말이 되는 글은 `<article>`, 연관된 내용들의 묶음은 `<section>`, 부가적인 정보는 `<aside>`로 구분합니다. 이렇게 하면 코드의 가독성이 높아지고 유지보수가 훨씬 쉬워집니다.
- `<img>` 태그의 `alt` 속성의 필요성과 작성 방법은?
  - alt(대체 텍스트)는 이미지가 로드되지 않았을 때 대신 텍스트를 보여주고, 시각 장애인이 스크린 리더를 사용할 때 이미지를 소리로 설명해 주는 핵심 속성입니다. 작성할 때는 "사진1"처럼 의미 없이 적기보다는 "별터의 직접 그린 공룡 행성이 프로필 그림"처럼 구체적이고 맥락을 알 수 있게 작성해야 합니다. 단순 장식용 이미지라면 `alt=""`로 비워두어 스크린 리더가 무시하도록 합니다.
- 상대 경로와 절대 경로를 혼용하면 어떤 문제가 발생할까?
  - 로컬 PC에서 개발할 때와 GitHub Pages 등에 배포했을 때의 기준 위치(Root)가 달라져서, 이미지가 엑스박스로 깨지거나 링크가 404 에러를 뿜으며 연결되지 않을 수 있습니다. 특히 배포 환경에서는 상대 경로(./images/)를 일관성 있게 사용하는 것이 안전합니다.

### CSS
- 9장의 이미지를 배치할 때, Flexbox와 CSS Grid 중 어떤 것이 더 적합할까?
  - CSS Grid가 훨씬 적합합니다. Flexbox는 주로 1차원(가로 또는 세로 한 방향) 배치에 특화되어 있지만, Grid는 2차원(행과 열을 동시에 제어) 배치에 최적화되어 있습니다. 이번 갤러리처럼 가로 3열, 세로 3행의 바둑판 형태를 만들 때는 `grid-template-columns: repeat(3, 1fr);` 한 줄로 깔끔하게 제어할 수 있는 Grid가 정답에 가깝습니다.
- 태그, 클래스, ID 선택자는 각각 언제 사용하는 것이 적절할까?
  - 태그 선택자: body, h1, p처럼 문서 전체의 굵직한 기본 폰트나 색상 베이스를 잡을 때 사용합니다.
  - 클래스(.) 선택자: .card, .btn처럼 여러 요소에 반복적으로 재사용할 스타일을 지정할 때 가장 널리 사용합니다.
  - ID(#) 선택자: #profile-hero처럼 페이지 내에서 단 한 번만 등장하는 고유한 특정 영역을 꾸미거나, JavaScript에서 요소를 정확히 찾아 제어해야 할 때 사용합니다.
  
### JavaScript
- `document.getElementById()`와 `document.querySelector()`의 차이는?
  - getElementById는 오직 ID 이름만으로 요소를 빠르게 찾습니다. 반면 querySelector는 CSS 선택자(.class, #id, 태그 > 클래스 등)를 그대로 사용할 수 있어 복잡한 조건의 요소를 찾을 때 훨씬 유연하고 직관적입니다. (단, 일치하는 요소가 여러 개라도 첫 번째 요소만 반환합니다.)
- `innerHTML`로 DOM을 조작할 때 주의해야 할 점은 무엇일까?
  - 가장 큰 문제는 XSS(크로스 사이트 스크립팅) 보안 취약점입니다. 사용자가 폼에 악의적인 `<script>` 코드를 입력했는데 그것을 innerHTML로 그대로 렌더링하면 브라우저가 스크립트를 실행해 버릴 위험이 있습니다. 단순 텍스트만 넣는다면 textContent를 쓰고, 이번 미션처럼 태그 구조를 추가할 때는 createElement로 안전하게 노드를 만들어 prepend나 appendChild로 붙이는 방식을 권장합니다.

### 배포
- 정적 배포된 페이지에서 작성한 TIL 데이터는 새로고침 시 어떻게 될까?
  - 새로 작성한 데이터는 모두 날아가고 화면이 초기화됩니다. 우리가 JavaScript로 추가한 요소들은 현재 접속 중인 브라우저 화면(임시 메모리)에만 그려진 것일 뿐, 실제 서버의 파일이나 데이터베이스에 저장된 것이 아니기 때문입니다.
- JavaScript로 추가한 데이터를 영구적으로 저장하려면 어떤 방법이 필요할까?
  - 가장 쉬운 방법은 브라우저가 제공하는 로컬 저장소(localStorage 또는 sessionStorage)를 활용하는 것입니다. 더 근본적인 해결책을 위해서는 백엔드 서버 환경(API)을 구축하고 데이터베이스(DB)를 연동하여 데이터를 전송 및 저장해야 합니다.
